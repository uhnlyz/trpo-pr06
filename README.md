# Практическая работа № 6 — PHP: файлы, JSON, сессии и подготовка к MVC

## Результат
Небольшой менеджер заметок. Приложение читает начальные записи из `dataset/notes.json`, при первом запуске создаёт рабочий файл `data/notes.json`, позволяет добавлять заметки и менять их статус. Имя пользователя хранится в PHP-сессии.

## Реализовано по заданию
- Единая точка входа `public/index.php`.
- Чтение JSON через `file_get_contents()` и `json_decode()` с `JSON_THROW_ON_ERROR`.
- Функции загрузки и сохранения JSON вынесены в `src/functions.php`.
- Добавление заметки через POST с проверкой обязательного поля и уникальным id.
- После POST выполняется redirect, чтобы обновление страницы не повторяло отправку.
- `session_start()` вызывается до HTML; имя пользователя хранится в `$_SESSION`.
- Имя берётся из `dataset/users.json`, есть действие очистки сессии.
- `dataset/session_scenarios.json` отображается в блоке проверки.
- Шаблоны находятся в `templates/`; `templates/list.php` получает подготовленные данные и отвечает за HTML.
- Есть страница `about` и обработка неизвестного `page` с HTTP-статусом 404.
- Отсутствующий рабочий файл создаётся из `dataset/notes.json`; повреждённый JSON приводит к понятному сообщению.

## Требования и запуск
Нужен PHP 8.0 или новее с поддержкой сессий. Composer и сторонние библиотеки не нужны.
Из корня проекта выполните:
```bash
php -S localhost:8000 -t public
```
Откройте `http://localhost:8000`.

## Как проверить
1. В обычном окне по умолчанию отображается «Гость».
2. Выберите `Student A`, сохраните имя и обновите страницу — имя должно остаться.
3. Очистите имя пользователя — снова появится «Гость».
4. Откройте приватное окно: там будет отдельная сессия.
5. Добавьте заметку: она должна появиться в списке и сохраниться в `data/notes.json`.
6. Измените статус заметки и обновите страницу.
7. Откройте `http://localhost:8000/?page=unknown`: должна появиться страница 404.
8. Удалите `data/notes.json`: приложение создаст его заново из dataset.
9. Для проверки повреждённого JSON временно нарушьте синтаксис `data/notes.json`: приложение должно показать понятное сообщение. После проверки восстановите файл из `dataset/notes.json`.

## Разделение обязанностей
```text
Браузер → public/index.php
             ├── src/functions.php — чтение/запись JSON и подключение шаблона
             ├── data/notes.json — рабочее файловое хранилище
             ├── $_SESSION — имя пользователя в текущей сессии
             └── templates/list.php — HTML подготовленных данных
```
Шаблон не открывает JSON и не изменяет `$_SESSION`. Подготовка данных и обработка запроса выполняются до его подключения.

## Ограничения
JSON подходит для небольшой учебной задачи, но не рассчитан на большое количество одновременных записей. В реальном приложении понадобились бы более строгая обработка конкурентного доступа, CSRF-защита, авторизация и база данных. Это подготовительный шаг к разделению обработчика и представления, а не полноценная MVC-архитектура.
