# Подготовка к защите — практическая работа № 6

## Что показать
1. Запустить `php -S localhost:8000 -t public`.
2. Показать список заметок из `data/notes.json`.
3. Добавить заметку и показать изменение JSON-файла.
4. Поменять статус заметки и обновить страницу.
5. Выбрать `Student A`, обновить страницу и показать сохранение имени в сессии.
6. Очистить имя, затем проверить приватное окно.
7. Показать сценарии из `dataset/session_scenarios.json`.
8. Открыть `?page=unknown` и показать страницу 404.
9. Открыть `templates/list.php` и объяснить, что он получает данные, а не читает JSON самостоятельно.

## Понятия простыми словами
- **JSON** — текстовый формат хранения структурированных данных.
- **`file_get_contents()`** — читает содержимое файла в строку.
- **`json_decode()`** — преобразует JSON-строку в PHP-массив.
- **`json_encode()`** — преобразует PHP-массив обратно в JSON.
- **`JSON_THROW_ON_ERROR`** — позволяет явно обработать ошибку разбора JSON.
- **`file_put_contents()`** — записывает данные в файл.
- **Сессия** — данные конкретного пользователя между запросами; в PHP доступ к ним идёт через `$_SESSION`.
- **`session_start()`** — начинает или продолжает сессию; вызывается до HTML.
- **Redirect после POST** — после обработки формы браузер перенаправляется на GET, чтобы обновление страницы не отправляло форму повторно.
- **Шаблон** — файл, который отвечает за HTML и получает подготовленные переменные.

## Контрольные вопросы
**1. Какие входные данные получает приложение и где они находятся?**  
Начальные заметки — `dataset/notes.json`, список пользователей — `dataset/users.json`, сценарии — `dataset/session_scenarios.json`. Рабочие заметки сохраняются в `data/notes.json`.

**2. Какой участок кода отвечает за преобразование данных в интерфейс?**  
`public/index.php` загружает данные и передаёт их в `templates/list.php` через `renderTemplate()`. Шаблон выводит подготовленные переменные.

**3. Какое ошибочное состояние проверялось?**  
Пустая заметка, отсутствие рабочего JSON-файла, повреждённый JSON и неизвестное значение параметра `page`.

**4. Что можно изменить при увеличении проекта?**  
Добавить Router, Controller, Repository, отдельные модели и базу данных. Сейчас `index.php` остаётся единой точкой входа и простым обработчиком запросов.

**5. Как проверить работу после чистого клонирования?**  
Установить PHP 8.0+, выполнить команду запуска из README и открыть `http://localhost:8000`. При отсутствии `data/notes.json` он создаётся из dataset.

**6. Чем серверное выполнение PHP отличается от JavaScript в браузере?**  
PHP выполняется на сервере и формирует ответ. JavaScript в браузере выполняется на стороне клиента.

**7. Когда полезен конструктор класса?**  
Когда нужно создать объект с обязательными начальными значениями. В этой работе классы не являются основной темой, но на следующем шаге они могут описывать заметки и пользователей.
